# Fixr API: frontend implementation guide

This document describes the HTTP API exposed by the Spring Boot application for frontend clients. It is based on the current controllers, request/response DTOs, services, and Spring Security configuration.

## Base URL and conventions

Use the deployed backend origin as the base URL. All application routes below are under `/api/v1`. Requests and JSON responses use `application/json` unless noted. IDs are UUIDs. Pagination is zero-based.

Send the login `accessToken` on authenticated requests as `Authorization: Bearer <accessToken>`. The login response also sets HTTP-only token cookies; JavaScript cannot read those cookies, so for a browser client configure requests with credentials if the frontend and API origins require cookie transport. CORS origins are configured by the backend. CSRF protection is disabled.

An optional or implicit guest is allowed for public feed reads. Those reads include viewer-specific vote data only when the backend resolves an authenticated viewer.

## Authentication

### `POST /api/v1/fixr/user/auth/signup`

Creates a user account. This is a controller endpoint and does not require authentication.

**Request body**

```json
{
  "firstname": "Ada",
  "middleName": null,
  "lastname": "Example",
  "email": "ada@example.com",
  "phoneNumber": "+2348000000000",
  "password": "at-least-8-characters",
  "isInNigeria": true,
  "agreedToTerms": true,
  "state": "Lagos",
  "lga": "Ikeja",
  "city": "Ikeja"
}
```

**Preconditions:** `firstname`, `lastname`, `password`, `state`, and `lga` are nonblank; `email` must be an email address; password length is at least 8; phone number length is 11–13 characters when supplied; `isInNigeria` and `agreedToTerms` must be present. `middleName`, `phoneNumber`, and `city` may be omitted/null. The backend creates or reuses state/LGA/city entries by name. A user with the same email blind index is returned rather than duplicated.

**Success:** `200 OK`, `FixrUserResponseDto` JSON: `username`, `firstname`, `middleName`, `lastname`, `email`, and `blindEmailIndex`. The username is generated by the backend. Password is not returned.

### `POST /api/v1/fixr/user/auth/login` (Spring Security filter)

This route is not declared in a controller: `JwtAuthenticationFilter` handles it as Spring Security's username/password authentication endpoint. It does not require an existing token.

**Request body**

```json
{ "username": "generatedUsername", "password": "your-password" }
```

Although the DTO property is named `username`, authentication derives the lookup key from that value as a blind index; supply the account identifier expected by the backend's authentication flow.

**Preconditions:** Valid JSON with `username` and `password` matching a registered account.

**Success:** `200 OK`, JSON `{ "type": "Bearer", "accessToken": "…", "refreshToken": "…" }`. The backend also issues `AccessToken` and `RefreshToken` HTTP-only cookies. Access token lifetime is configured in backend security properties (30 minutes in the checked-in development configuration); refresh lifetime is configured there as well (7 days in development).

**Failure:** Invalid credentials are rejected by Spring Security (normally `401 Unauthorized`).

## Public report feed

### `GET /api/v1/fixr/feed`

Authentication: **not required**. Optional bearer authentication enables the `viewerVote` field.

Query parameters (all optional):

| Parameter | Default | Meaning |
| --- | --- | --- |
| `category` | `*` | Category filter; `*` means no category restriction. |
| `status` | `ALL` | `ReportStatus`: `Submitted`, `Processing`, `DuplicateDetected`, `Failed`, `Deleted`, `Published`, or `ALL`. |
| `state` | `*` | State filter; `*` means no state restriction. |
| `pageNum` | `0` | Zero-based page index. |
| `pageSize` | `40` | Page size. |
| `order` | `desc` | Ordering direction as interpreted by the feed service. |

**Preconditions:** `status` must be a valid enum name; pagination and order are passed to the feed service. The controller does not declare explicit range validation for these values.

**Success:** `200 OK`, Spring Data `PagedModel<ReportFeedResponseDto>`. Each report has `reportId`, `description`, `location`, `reporter`, `distance`, `mediaList`, `status`, `category`, `createdAt`, `upvoteCount`, `downvoteCount`, and optionally `viewerVote` (`UPVOTE` or `DOWNVOTE`).

### `GET /api/v1/fixr/feed/reports/{reportId}`

Authentication: **not required**; optional authentication supplies viewer-specific vote data.

**Preconditions:** `reportId` must be a UUID identifying an existing report.

**Success:** `200 OK`, one `ReportFeedResponseDto` with report details and vote totals. Invalid IDs return `400`; a missing report returns `404`.

### `GET /api/v1/fixr/feed/reports/{reportId}/comments`

Authentication: **not required**.

Query parameters: `pageNum` (default `0`) and `pageSize` (default `20`). `pageNum` must be at least 0; `pageSize` must be 1–100.

**Preconditions:** `reportId` must be a UUID for an existing report.

**Success:** `200 OK`, paged `ReportCommentResponseDto` items: `commentId`, `content`, `username`, `createdAt`, and `updatedAt`, ordered newest first. Invalid report IDs return `400`, missing reports return `404`, invalid pagination returns `400`.

### `POST /api/v1/fixr/feed/reports/{reportId}/comments`

Authentication: **required**.

Request body: `{ "content": "Comment text", "idempotencyKey": "unique-client-key" }`. `content` must be nonblank and at most 5,000 characters; `idempotencyKey` must be nonblank.

**Preconditions:** Valid report UUID for an existing report, authenticated user, and valid body. A repeated idempotency key returns the previously stored comment.

**Success:** `201 Created`, `ReportCommentResponseDto`.

### `PATCH /api/v1/fixr/feed/report/{reportId}/comments/{commentId}`

Authentication: **required**.

Request body: `{ "content": "Updated comment", "idempotencyKey": "required-but-not-used-for-edit" }`. Both fields are validated as nonblank; content is limited to 5,000 characters. The idempotency key is required by the DTO but not used by the edit operation.

**Preconditions:** Both IDs must be UUIDs, the comment must belong to the report, and the caller must be the comment author.

**Success:** `200 OK`, updated `ReportCommentResponseDto`. Missing comment returns `404`; a different author receives `403`; invalid content or IDs returns `400`.

### `DELETE /api/v1/fixr/feed/reports/{reportId}/comments/{commentId}`

Authentication: **required**.

**Preconditions:** Both IDs identify an existing report/comment pair. Caller must be the comment author or report owner.

**Success:** `204 No Content`. Missing report/comment returns `404`; unauthorized owner/author returns `403`.

### `PUT /api/v1/fixr/feed/reports/{reportId}/vote`

Authentication: **required**.

Request body: `{ "vote": "UPVOTE" }`, where `vote` is `UPVOTE` or `DOWNVOTE`.

**Preconditions:** Existing report, valid vote enum, authenticated user. Repeating the request changes/replaces that user's vote for the report.

**Success:** `200 OK`, `{ "viewerVote": "UPVOTE", "upvoteCount": 1, "downvoteCount": 0 }` (counts reflect the resulting vote state).

### `DELETE /api/v1/fixr/feed/reports/{reportId}/vote`

Authentication: **required**.

**Preconditions:** `reportId` must be a UUID for an existing report.

**Success:** `204 No Content`. If the user has not voted, the operation is a no-op. Invalid ID returns `400`; missing report returns `404`.

## User and report management

All routes in this section require authentication except signup, documented above. Account ownership is determined by the authenticated account.

### `GET /api/v1/fixr/user`

Returns the current user's `FixrUserResponseDto` (`username`, `firstname`, `middleName`, `lastname`, `email`, `blindEmailIndex`). Success: `200 OK`. No request body.

### `PATCH /api/v1/fixr/user`

**Declared but not implemented:** controller currently returns `null`. Do not rely on this endpoint for profile updates.

### `DELETE /api/v1/fixr/user`

**Declared but not implemented:** controller currently returns `null`. Account deletion is not available through this endpoint in the current implementation.

### `POST /api/v1/fixr/user/reports`

Creates a report for the authenticated user. Request body:

```json
{
  "description": "Description of the issue",
  "category": "Roads",
  "isAnonymous": false,
  "mediaList": [{ "mediaUrl": "https://example.com/photo.jpg", "mediaType": "Image" }],
  "locationDto": {
    "coordinates": { "longitude": 3.3792, "latitude": 6.5244 },
    "state": "Lagos",
    "lga": "Ikeja",
    "city": "Ikeja"
  },
  "idempotencyKey": "unique-client-key"
}
```

`category`, `locationDto`, and `idempotencyKey` are required. Location requires non-null longitude/latitude and nonblank state/LGA; city is optional. Each media item requires nonblank `mediaUrl` and `mediaType` (`Image` or `Video`). `description`, `isAnonymous`, and `mediaList` are nullable at DTO validation level.

**Postconditions:** The report is saved (or the existing report for the same idempotency key is returned) and an asynchronous embedding/duplicate-detection task is published. Initial and later report status depends on asynchronous processing; the report response contains `reportId`, `description`, `location`, `status`, `reportMedia`, `category`, and `createdAt`.

Success: `200 OK`, `UserReportResponseDto`.

### `GET /api/v1/fixr/user/reports`

Returns the authenticated user's submitted reports only. Query: `pageNum` (default `0`) and `pageSize` (default `20`). Success: `200 OK`, paged `UserReportResponseDto` items. The service sorts by update time descending. The controller does not declare explicit pagination range validation.

### `GET /api/v1/fixr/user/report/{reportId}`

Returns one report owned by the authenticated user. `reportId` must identify the caller's report. Success: `200 OK`, `UserReportResponseDto`; a report not owned by the caller is reported as not found by the service.

### `PATCH /api/v1/fixr/user/reports?reportId={reportId}`

**Declared but not implemented:** controller currently returns `null`; no update request schema or postcondition is implemented.

### `DELETE /api/v1/fixr/user/reports/{reportId}`

Soft-deletes the caller's report by setting its status to `Deleted`; it does not physically remove the row. Preconditions: existing report UUID owned by caller. Success: `200 OK` with an empty body. A different owner is rejected. A malformed/missing ID may result in an error from UUID/database lookup.

### `GET /api/v1/fixr/user/reports/{reportId}/duplicate-candidates`

Authentication: **required**; the caller must own the report. Standard Spring `page`, `size`, and `sort` pageable parameters are accepted.

Success: `200 OK`, paged `DuplicateCandidateResponseDto` items with `reportId`, `description`, `rank`, `similarityScore`, and nullable `distanceMeters`. A report not owned by the caller is returned as not found.

## Response and error notes

- Successful status codes above are taken from the controller/filter implementation. Validation and security failures are handled across Spring MVC/Security; exact error JSON is not standardized in the current README/source contract.
- Public feed reads can be used without credentials. All other routes are protected by Spring Security's `anyRequest().authenticated()` rule except the explicitly permitted signup/login and API documentation routes.
- Login is handled by the custom Spring Security filter at `/api/v1/fixr/user/auth/login`; form login and HTTP Basic are disabled.
- `PATCH /api/v1/fixr/feed/report/...` uses a singular path segment, while adjacent report routes use plural `/reports/`.
- The account/profile and report update controller methods listed above are placeholders that currently return `null`.
